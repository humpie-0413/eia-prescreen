## Phase 1: 프로젝트 전수조사 (dispatching-parallel-agents 활용)

병렬 에이전트 5개를 동시에 실행하여 다음 영역을 조사해줘.
각 에이전트의 결과를 docs/PROJECT_AUDIT.md에 통합 작성할 것.

### Agent 1: 백엔드 아키텍처 조사
- backend/app/ 전체 디렉토리 구조 매핑
- 모든 서비스 파일 목록 + 각 서비스의 역할 1줄 설명
- 모든 API 엔드포인트 목록 (라우터별 정리)
- 의존성 그래프 (어떤 서비스가 어떤 서비스를 호출하는지)
- 외부 API 연동 현황 (URL, 인증방식, 상태)
- 데이터 저장소 구조 (인메모리, 파일, ChromaDB)

### Agent 2: 프론트엔드 구조 조사
- frontend/src/ 전체 디렉토리 구조 매핑
- 모든 페이지/라우트 목록 + 각 페이지 기능 1줄 설명
- 공통 컴포넌트 목록
- API 호출 함수 목록 (api.ts 분석)
- 사용 중인 라이브러리 (package.json 분석)
- 빌드 설정 (next.config.js 분석)

### Agent 3: 데이터·규칙 자산 조사
- data/ 전체 디렉토리 구조 + 파일 크기
- 커넥터 14개 각각의 데이터 소스, 갱신 주기, 데이터 건수
- 규칙 YAML 파일별 규칙 수 + 커버하는 도메인
- 규제 매핑 YAML 파일별 매핑 수
- 유사사례(cases.json) 총 건수 + 유형별 분포
- 패턴 데이터 (patterns_by_type.json) 17개 유형별 사례 수
- RAG 시스템: 보고서 수, 청크 수, 유형별 분포
- 벌크 데이터: 9,973건 협의 기록 구조

### Agent 4: 테스트·품질 조사
- pytest 테스트 파일별 테스트 수 + 커버리지
- Playwright E2E 테스트 파일별 시나리오 수
- 현재 테스트 실행 결과 (pytest 실행)
- pnpm build 결과
- TypeScript 에러 현황
- 알려진 이슈/TODO 목록 (코드 내 TODO/FIXME 검색)

### Agent 5: 문서·이력 조사
- docs/ 디렉토리의 모든 문서 목록 + 각 문서 요약 1줄
- .env.example 또는 .env 구조 (키 이름만, 값 제외)
- Dockerfile 존재 여부 + 내용 요약
- .gitignore 내용
- README.md 존재 여부 + 내용
- 배포 관련 설정 (vercel.json, railway.json 등)

## Phase 3: 실무 확장 계획 수립 (writing-plans + brainstorming 활용)

전수조사 결과를 바탕으로 docs/PRODUCTION_PLAN.md를 작성:

### 목표
- 현재: 포트폴리오 수준의 사전검토 보조 도구
- 목표: 환경영향평가 대행업체가 실무에 사용할 수 있는 수준

### 확장 방향 4개 축
1. 데이터 완결성 — 20개 평가항목 완전 커버
2. 법령 최신성 — 개정 자동 감지 + 관리자 반영
3. 보고서 전문성 — 가이드라인 21항목 초안 생성
4. 운영 안정성 — DB 영속화, 사용자 관리, 감사 로그

### Step별 실행 계획
각 Step에:
- 목표 (1줄)
- 수정 대상 파일 목록
- 수락 기준 (측정 가능)
- 예상 소요 시간
- Claude Code 실행 프롬프트 (바로 붙여넣기 가능)

### 우선순위 기준
- 실무 임팩트 × 구현 난이도 매트릭스
- 공공 API 존재 여부 (있으면 우선)
- 기존 커넥터 패턴 재사용 가능 여부
